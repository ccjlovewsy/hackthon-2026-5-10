
## `.mjs` 文件说明

本项目后端大量使用 `.mjs` 后缀，说明如下：

`.mjs` = **Module JavaScript**，就是 ES Module 的文件后缀。

### 它解决什么问题

Node.js 有两套模块系统：

| 后缀     | 模块系统         | 写法                               |
| -------- | ---------------- | ---------------------------------- |
| `.js`  | CommonJS（默认） | `require()` / `module.exports` |
| `.mjs` | ES Module        | `import` / `export`            |
| `.cjs` | 强制 CommonJS    | `require()`                      |

`.mjs` 显式告诉 Node：“用 ES Module 解析这个文件”，不管 `package.json` 里 `"type"` 是什么。

### 为什么这个项目用 `.mjs`

看 `package.json`:

```json
"type": "module"
```

设了 `"type": "module"` 后，项目里所有 `.js` 都会被当 ES Module 处理。这时其实 `.js` 和 `.mjs` 等价——作者用 `.mjs` 只是个习惯/显式标注，强调“这是 ESM，不是 CommonJS”。

### 语法对比

CommonJS（你熟悉的）：

```javascript
const express = require('express');
module.exports = { foo };
```

ES Module（`.mjs` 用的）：

```javascript
import express from 'express';
export const foo = {};
export default { foo };
```

关键差异：

- **import 是静态的**，在文件顶部，会被提升和 tree-shake
- **import 必须带后缀**：`import { x } from './utils.mjs'`（不能省 `.mjs`，这点和 CommonJS 的 `require('./utils')` 不同）
- **顶层 await 可用**（Node 14.8+）
- **`__dirname` / `__filename` 不存在**，要用 `import.meta.url` 自己算

### 给 Java/Python/Go 背景的一句话

它就是 JavaScript 版的“标准模块系统”，类似 Java 的 `import`、Python 的 `import`、Go 的 `import`。Node 早期只有 CommonJS（`require`），后来标准化成 ESM（`import`），现在 ESM 是官方推荐方向，新项目基本都用它。

## 为什么 LLM/RAG 项目用 `.mjs`（Node）来写

很多人以为“做 LLM/RAG 就得用 Python”，其实是个常见误解。澄清如下：

### LLM/RAG 项目 ≠ 必须 Python

LangChain 有两个官方维护的版本：

| 语言     | 包                                      |
| -------- | --------------------------------------- |
| Python   | `langchain` (pip)                       |
| JS/TS    | `langchain` / `@langchain/*` (npm) ← 本项目用的 |

看 `package.json`：

```json
"@langchain/core": "^0.3.79",
"@langchain/openai": "^0.5.18",
"@langchain/textsplitters": "^0.1.0",
```

这就是 LangChain 的 JS 版，功能上和 Python 版对等（agents、chains、retrievers、text splitters 都有）。

### 为什么这个项目选 Node 而不是 Python

几个实际原因（对黑客松场景特别成立）：

1. **单语言全栈**：前端 Cytoscape/ECharts 可视化 + 后端 RAG，都用 JS，一套语言打通前后端，部署只要 `npm start`。
2. **LangChain.js 0.3+ 基本只出 ESM**：`@langchain/core` 等包的新版本是 ESM-only/ESM-first。要用它，项目就得是 ESM（`"type": "module"`），文件就是 `.mjs` 或 ESM 的 `.js`。
3. **OpenAI SDK v5、Vectra 也都偏 ESM**：配套生态一起走 ESM。
4. **部署简单**：黑客松评委 `npm install && npm start` 就跑，不用配 Python 环境/venv/pip。

### Python 才做 LLM 的印象从哪来

因为大部分 RAG 教程、LangChain 文档示例、LlamaIndex 等都是 Python 优先。但那只是文档生态偏向，不代表技术能力。Node 端该有的都有：embedding、向量库（Vectra/Pinecone/Chroma）、RAG、agent、function calling。

### 一句话总结

**`.mjs` 和“是不是 LLM/RAG 项目”没关系**——它只跟“用 Node 写、且依赖了 ESM-only 的库”有关。这个项目用 Node 是为了前后端单语言 + 部署简单，用 `.mjs` 是因为 LangChain.js 新版本要求 ESM。
