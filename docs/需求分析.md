# 需求分析

## 1. 知识点粒度

系统将教材先解析成“教材 - 章节 - 正文”的层级 JSON，再以章节为基本抽取单元生成知识点图谱。每章默认限制在 12 个核心知识点以内，避免把教材句子逐条拆成碎片，也避免只保留章标题导致粒度过粗。知识点覆盖概念、机制、结构、过程、方法、疾病等类型，并保留章节、页码、原文短摘录和定义，便于教师检查来源。章节主题节点仅用于前端聚类和导航，不计入事实关系统计，从而区分“展示结构”和“教材真实知识关系”。

## 2. 重复判定

跨教材整合的核心问题不是简单字符串去重，而是判断两个知识点是否在教学语义上等价。系统先用 Dice 二元 n-gram、名称归一化、定义相似度等 lexical 方法召回候选，再交给 LLM 进行同义词、简称、外文名和表述差异的语义判定。所有 `merge`、`remove`、`keep` 决策前都必须输出 `necessity.necessary` 和 `necessity.reason`；缺少必要性判断会触发 `NEED_NECESSITY_JUDGEMENT`。这样可以降低 LLM 因相似措辞误合并上下位概念、前置依赖或应用场景不同知识点的风险。

## 3. 教学连贯性

知识图谱不仅要压缩重复内容，还要保留学习顺序和概念之间的教学连贯性。系统将关系类型限定为 `prerequisite`、`parallel`、`contains`、`applies_to` 四类：分别表达先修依赖、同层并列、组成包含和知识应用。整合时会保留节点来源、章节页码和关系端点，教师还可以通过对话反馈要求保留、删除、拆开或解释某个节点。对话历史持久化到本地 JSON，前端刷新整合图后能继续围绕已有决策迭代，形成“算法建议 - 教师校正 - 图谱更新”的闭环。

## 4. 压缩比

赛题要求在去重整合时兼顾信息压缩与教学完整性，因此系统把目标压缩比设为 30%。统计口径分为两层：原始教材压缩比使用 `integrated_chars / original_chars`，其中原始字数来自预解析教材 JSON 的 `total_chars` 或章节 `char_count`；图谱压缩比使用整合后保留节点定义字数与原始节点定义字数对比。整合模块会输出 `raw_node_count`、`current_node_count`、`action_counts`、`decision_count` 和 `compression_ratio` 等指标，报告页据此展示整合前后节点数量、关系数量和决策分布，便于评委复核。

## 5. RAG 分块策略

RAG 问答要求回答必须可追溯到教材原文，因此 chunk 需要同时覆盖完整定义、机制说明和来源元数据。系统默认使用 700 字 chunk、80 字 overlap：700 字处于赛题要求的 500-800 字中段，通常能容纳教材中一个概念的定义、解释和短例子；80 字重叠处于 50-100 字范围内，可降低关键定义跨块截断风险。每个 chunk 保存教材名、章节标题、页码和 `source_ref`，问答时检索 top-5 chunk 并要求 LLM 只基于上下文回答。若答案缺少引用或包含不存在的引用，后处理会自动补齐或移除，保证引用来源可查。
