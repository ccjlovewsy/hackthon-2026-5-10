# 飞书桥发文件权限缺失 —— 2026-08-12

> 关联文档：`docs/superpowers/reviews/飞书桥崩溃排查-2026-08-11.md`
> 现象：飞书 × opencode 桥处理入站文件并产出 HTML 后，回发文件给用户时返回 400，应用缺少飞书 API scope。

- **用户感知**：飞书会先收到一条「❌ 发文件失败:Request failed with status code 400」的兜底文本消息。

## 二、根因

### 主因：应用未开通 `im:resource:upload` / `im:resource` scope

`src/feishuBot.mjs:88-120` 的 `sendFileToFeishu` 函数，发文件分两步：

```js
// feishuBot.mjs:98-100 — 第一步：上传文件资源
const uploadResp = await client.im.file.create({
  data: { file_type: "stream", file_name: fileName, file: fileBuf },
});
```

`client.im.file.create` 对应飞书 OpenAPI「上传文件」(`/im/v1/files`)，要求**应用身份**具备以下任一 scope：

- `im:resource:upload`（仅上传）
- `im:resource`（资源完整读写）

当前应用 `cli_aaf3f9f709b91be4` 在飞书开发者后台未开通这两个权限中的任何一个，于是上传文件这一步直接返回 400 + 错误码 `99991672`（"Access denied"）。

### 次要：异常被吞，链路未中断

`sendFileToFeishu` 在 `catch` 块里只做了日志 + 兜底文本回复，没有向上抛错，所以 opencode 那边的会话 `ses_01049a942ffenExFUVnTJQPkKg` 继续走完后续步骤。但这意味着用户**不会**在飞书看到「下载 HTML 文件」按钮，只能看到一个失败提示。

## 四、修复建议

### P0 — 在飞书开发者后台开通任一权限

应用 ID：`cli_aaf3f9f709b91be4`

直接链接（已带目标 scope 参数）：

```
https://open.feishu.cn/app/cli_aaf3f9f709b91be4/auth?q=im:resource:upload,im:resource&op_from=openapi&token_type=tenant
```

推荐开通 **`im:resource:upload`**（最小权限原则，只需要上传不需要读取其他资源）。开通后需要发布新版本或重新申请应用版本审核（企业自建应用通常即时生效）。

### P1 — 启动时自检 scope

`feishuBot.mjs` 启动时调一次 `client.authen.accessToken.get` 或读取 `application` API 检查应用 scope 列表，发现缺 `im:resource:upload` 时，主动打印警告（甚至飞书播报一条提醒）。避免下次用户重试时还卡在同一处。

### P2 — 错误回复更具体

当前 `catch` 只输出 `err?.message`（"Request failed with status code 400"），对用户毫无信息量。建议解析飞书 SDK 的 `err.code`：

```js
} catch (err) {
  const feishuCode = err?.response?.data?.code ?? err?.code;
  const hint = feishuCode === 99991672
    ? "（缺 im:resource:upload 权限，请在飞书后台开通）"
    : "";
  logger.error("feishuBot", `发文件失败 code=${feishuCode}`, err);
  await sendToFeishu(chatId, `❌ 发文件失败${hint}:${err?.message ?? err}`).catch(() => {});
}
```

## 五、验证

1. **开通权限后**：在飞书发一条「把 stackmap-card.html 发给我」指令，期望桥成功调用 `client.im.file.create` → `client.im.message.create`，飞书侧收到可下载的 file 消息，日志出现 `已发文件 chat=... message_id=...`。
2. **权限未开通时**：期望启动日志有明确警告（P1 落地后），而非等到用户实际触发放文件才报错。
3. **错误提示**：P2 落地后，临时撤销权限触发一次发文件，期望飞书收到的文本里包含「缺 im:resource:upload 权限」字样，便于运维定位。
