# 飞书 × Agent 桥接系统技术介绍

> 版本：2026-11-19  
> 项目：`feishu-opencode-bridge`  
> 读者：需要理解、部署或继续开发该系统的工程人员

## 1. 项目概述

本项目把飞书单聊接入本机 agent 执行环境。用户在飞书中发送自然语言指令，桥接进程将指令交给 opencode 或 DeepSeek Harness（DSH）执行，再把结果返回飞书。

系统不是简单的消息转发器，而是提供一套完整的远程 agent 使用方式：

- 连续、多轮对话，并持久化聊天与 agent 会话的对应关系。
- 对敏感工具操作进行人工审批，避免 agent 未经确认直接执行。
- 支持文件收发、视频总结、会话日志查询和健康指标读取。
- 对进程崩溃、连接中断、会话失效和重复消息进行专门防护。
- 同时支持 opencode 与 DSH ACP 两种后端，并保留快速回退能力。

模块从黑客松主项目 `hackthon-2026-5-10` 拆分为独立目录，与主项目的教材业务解耦。

## 2. 建设目标

系统主要解决四类问题：

1. **入口问题**：让飞书成为本机 agent 的轻量交互入口，无需持续打开终端。
2. **安全问题**：写文件、执行 shell、申请沙箱提权等操作必须经过用户确认。
3. **连续性问题**：同一飞书聊天持续使用同一 agent 会话，重启后尽量恢复上下文。
4. **稳定性问题**：避免长时间运行后出现进程退出、旧会话卡死、指令重复执行和故障不可见。

## 3. 总体架构

```text
飞书单聊
  │ WebSocket 长连接
  ▼
feishuBot.mjs
  │ 负责初始化、后端选择、飞书回调和 HTTP 服务
  ▼
feishuBotCore.mjs
  │ 负责消息归一化、授权、去重、路由、队列和会话管理
  │
  ├── createOpenCodeServer()
  │     └── opencode serve HTTP API
  │
  └── createDshAcpServer()
        └── dsh --profile acp
              └── ACP stdio JSON-RPC
```

入口和核心逻辑均位于 `src/`。核心层不依赖飞书 SDK，因此消息路由、审批和会话行为可以直接使用 `node:test` 测试。

### 3.1 外围服务

- `logger.mjs`：输出带时间、级别和 scope 的结构化日志。
- `globalErrorHandler.mjs`：记录未捕获异常和未处理 rejection，防止进程直接退出。
- `healthServer.mjs`：提供 `/health` 和 `/metrics`。
- `progressServer`：提供 `POST /progress`，供外部脚本推送进度。
- `sessionLog.mjs`：按 chat 持久化指令和回复，支持 `/log` 查询。

## 4. 双后端设计

后端通过 `AGENT_BACKEND` 选择，默认值为 `opencode`。

| 能力 | opencode | DSH ACP |
|---|---|---|
| 协议 | HTTP + SSE | ACP stdio JSON-RPC |
| 创建会话 | `POST /session` | `session/new` |
| 恢复会话 | 按 sessionID 继续使用 | `session/resume` |
| 发送指令 | `POST /session/{id}/message` | `session/prompt` |
| 审批事件 | `permission.asked` | `session/request_permission` |
| 会话重置 | 清理桥内映射和队列 | `session/cancel` + `session/close` |
| 永久允许 | 支持当前会话内同范围放行 | 不支持，明确降级为单次允许 |
| 会话映射 | `data/feishu-sessions.json` | `data/dsh-feishu-sessions.json` |

两个后端共用飞书侧的白名单、去重、串行队列、审批文案、文件、视频、日志和健康检查逻辑。

DSH ACP 适配器位于 `src/dshAcpServer.mjs`。它还会缓存 `session/update` 中的 `tool_call.title` 和 `rawInput`，在权限请求只携带 `toolCallId` 时补齐工具名称、命令和文件路径，避免飞书审批消息出现 `undefined`。

## 5. 核心业务流程

### 5.1 文本指令

1. 接收 `im.message.receive_v1` 事件并提取文本。
2. 校验发送者是否在 `OPENCODE_ALLOWED_USERS` 白名单中。
3. 按 `message_id` 去重，按 `chatId` 进入串行队列。
4. 查找或创建该 chat 对应的 agent 会话。
5. 调用当前后端执行指令，收集 assistant 文本。
6. 将结果返回飞书，同时写入结构化日志和 chat 会话日志。

同一 chat 的会话会持续复用；不同 chat 使用不同的 sessionID，互不共享执行队列。

### 5.2 敏感操作审批

1. 后端发起权限请求。
2. 桥根据 sessionID 找到对应飞书 chat，并将工具、命令和文件信息发送给用户。
3. 用户回复「允许」「拒绝」或带编号的审批指令。
4. 桥将选择映射为后端决定：opencode 的 `once/reject`，或 ACP 的 `allow-once/reject-once`。
5. 后端继续或中止操作，桥返回处理结果。

找不到 chat 的权限请求会自动拒绝。`拒绝。`、`允许，` 等带标点回复也能识别，避免被误当成新指令。

DSH 不支持 `allow-always`。用户回复「总是允许」时，桥会明确提示“DSH 后端暂只支持单次允许”，不会虚假宣称已自动放行。

### 5.3 `/kill` 与 `/log`

`/kill`（或 `/reset`）用于会话卡死时的人工逃生：

- 清除该 chat 的会话映射、串行队列和待审批请求。
- 增加会话代次，阻止旧任务覆盖新会话或继续回复过期结果。
- DSH 后端只取消并关闭当前 chat 的会话，不重启整个 ACP 进程，不影响其他 chat。

`/log tail [N]`、`/log head [N]`、`/log grep <关键字>` 和 `/log cat` 可直接在飞书中查询当前 chat 的历史指令与回复。

## 6. 可靠性设计

| 机制 | 作用 |
|---|---|
| 全局异常处理 | 未捕获异常只记录，不直接导致桥进程退出 |
| `fetchWithRetry` | 为 opencode HTTP 请求提供业务超时、指数退避和有限重试 |
| 禁止指令 POST 重试 | 防止网络异常导致同一指令被重复执行 |
| 串行队列 | 避免同一 chat 的并发指令相互覆盖 |
| 消息去重 | 拦截飞书长连接的重复事件推送 |
| 会话失效自愈 | 对明确的 404 会话错误自动重建会话 |
| ACP 惰性恢复 | 重启后按已有 DSH sessionID 调用 `session/resume` |
| 断线结果未知 | prompt 接受后断线时不自动重发，提示用户确认 |
| `/kill` 代次隔离 | 旧任务不得覆盖新会话或发送过期结果 |
| 待审批清理 | `/kill` 同时清理旧权限请求，防止答复失效审批 |
| 结构化日志 | 统一记录启动、指令、权限、错误和恢复过程 |
| 健康指标 | 提供消息、审批、会话和重连计数，便于观察运行状态 |

这里的关键原则是：**网络重试可以恢复读取操作，但不能盲目重放可能产生副作用的 agent 指令。**

## 7. 文件与视频能力

- `/file <path>`：将工作目录子树内的文件发送到飞书，阻止越界路径和不支持的扩展名。
- 入站文件：通过飞书消息资源接口下载，再包装成 agent 指令处理。
- 视频链接：支持 YouTube、bilibili 和 `b23.tv` 短链，先尝试字幕；无字幕时使用 Whisper API 或本地 whisper。
- 长字幕：分块总结后再合并，避免单次上下文过长。

这些外围能力与后端选择无关，切换后端时无需重写。

## 8. 持久化与日志

```text
data/
├── feishu-sessions.json       opencode chat_id → sessionID
├── dsh-feishu-sessions.json   DSH chat_id → sessionID
├── feishu-bot.log             桥结构化运行日志
├── session-logs/<chatId>.log  每个 chat 的 USER / ASSISTANT / ERROR 记录
└── opencode-logs/             launchd 与后端输出
```

会话映射采用临时文件写入后重命名的方式，避免半写状态。运行态数据和密钥文件不进入 git。

## 9. 部署配置

主要环境变量：

| 变量 | 用途 |
|---|---|
| `FEISHU_APP_ID` / `FEISHU_APP_SECRET` | 飞书自建应用凭据 |
| `OPENCODE_DIR` | agent 的工作目录 |
| `OPENCODE_ALLOWED_USERS` | 允许使用桥的用户 ID 列表 |
| `AGENT_BACKEND` | `opencode` 或 `dsh-acp` |
| `DSH_CMD` / `DSH_ARGS` | DSH 启动命令及前置参数 |
| `DSH_PROFILE` | DSH profile，默认 `acp` |
| `DSH_HOME` | DSH 持久化与 profile 根目录 |
| `DSH_CWD` | DSH 子进程启动目录，源码启动时指向 DSH 仓库 |

当前源码启动方式：

```dotenv
AGENT_BACKEND=dsh-acp
DSH_CMD=pnpm
DSH_ARGS=dsh
DSH_CWD=/Users/issuser/code/deepseek-harness
OPENCODE_DIR=/Users/issuser/code
```

DSH 与 opencode 的会话 ID 不通用，因此必须使用不同的映射文件。切换后端时，旧后端的映射文件保持不变。

同一个飞书应用不能同时运行两个长连接，否则会发生事件竞争。灰度时应先停止旧桥，或使用另一个飞书应用。

## 10. 回退设计

切换前的 launchd plist 保存在：

```text
tmp/launchd-backup/com.hackthon.feishu-opencode-bridge.before-dsh-acp.plist
```

回退到 opencode：

```bash
cp tmp/launchd-backup/com.hackthon.feishu-opencode-bridge.before-dsh-acp.plist \
  ~/Library/LaunchAgents/com.hackthon.feishu-opencode-bridge.plist
launchctl bootout gui/$(id -u)/com.hackthon.feishu-opencode-bridge
launchctl bootstrap gui/$(id -u) \
  ~/Library/LaunchAgents/com.hackthon.feishu-opencode-bridge.plist
```

opencode 的 `data/feishu-sessions.json` 不会因 DSH 灰度而被修改，因此可以恢复原有聊天会话。

运行：

```bash
npm test
```

当前共有 **109 项测试，全部通过**，覆盖：

- 消息提取、白名单、去重和审批文本解析。
- 会话失效自愈、`/kill`、空闲检测、日志和健康端点。
- ACP 会话复用与多 chat 隔离。

真实联调还验证了：

- DSH 两轮文本和跨进程恢复。

## 12. 技术栈

- Node.js >= 20，ESM `.mjs`
- `@larksuiteoapi/node-sdk`：飞书长连接和 IM API
- `@agentclientprotocol/sdk` 1.4.0：DSH ACP stdio JSON-RPC
- `dotenv`：环境变量加载
- `undici`：opencode 请求的连接层超时控制
- `node:test`：单元与行为测试

## 13. 当前边界与后续方向

当前需要保留的约束：

- DSH 只支持一次性审批，不提供 `allow-always`。
- ACP 面向自动化，不包含 DSH 专用 UI、终端或 elicitation 能力。
- 断线后的执行结果可能无法确定，系统选择提示用户，而不是自动重放指令。
- 生产切换仍应经过飞书真实链路验证和稳定观察期，不能只依据单元测试。

后续可考虑：

- 将飞书封装为 DSH 原生 Cordis 插件，减少独立桥进程。
- 增加多 chat 的真实并发验收和更完整的监控告警。
- 完善文件、视频和长任务的统一进度呈现。
- 在保留 opencode 回退路径的前提下，逐步评估 DSH 作为默认后端。
